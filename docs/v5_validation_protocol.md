> 建立日期：2026-08-20
>
> 状态：`draft_blocked`
>
> 适用范围：藕塘（Ootang）内部研发与后续正式验证设计
>
> 当前结论：**不得启动正式 v5 训练、NGBoost 推理、融合、阈值定型或正式预警输出。**

## 1. 文档目的与当前边界

本协议用于把“候选展示”与“正式验证”分开，并在实现正式 v5 前冻结标签、时间切分、比较基线、指标、阈值选择和缺失 V0 的处置规则。任何代码或结果只有在本协议的全部硬门通过后，才可使用“正式 v5 验证”表述。

当前已存在的 `ootang-v5-candidate-display-v1` 仅为探索性候选展示：

- `candidate_display_only=true`；
- `candidate_warning_color_output=false`；
- `ngboost_inference_output=false`；
- `v5_fusion_output=false`；
- `formal_warning_output=false`；
- `vajont_used=false`。

它展示位移、速度、原始 `ΔV`、区间状态以及在 V0 可用时的速度比和切线角，但没有正式标签、NGBoost 概率、融合等级或站点/滑坡体正式预警颜色。任何图中的 `interval_level` 是原始区间状态，`v4_reference_*` 是历史 v4 参考；二者都不能被改名或解释为 v5 真值或 v5 正式输出。

### 1.1 机器状态源与运行时守卫

`config/ootang_v5_gate_register.v1.json` 是 G0--G4 当前状态的唯一
机器权威源；本文档和 `docs/v5_g1_g4_preflight.md` 只解释证据与待决策
项，不能通过修改文字把 Gate 升格为 PASS。该 v1 register 本身也是冻结的
blocked snapshot，不得就地把 G1--G4 状态改为 PASS。当前有效结论为
`G0=PASS`、`G1=BLOCKED`、`G2=BLOCKED`、`G3=BLOCKED`、
`G4=BLOCKED`。当前 G5a 仍未评估且未授权，报告中固定为 false。

将来若要解除任一 blocker，必须保留 v1，新建 schema/version 与对应 manifest，
锁定新决策、批准和证据的交叉哈希，为新版本实现对应 validator，并在审查后
显式切换生产默认源。不得通过编辑 v1 的 `declared_status`、传入临时路径或
覆盖 root 来跳过版本切换。

`code/warning/ootang_v5_gate_preflight.py` 只校验 register 结构、决策完整性、
证据路径与 SHA-256；它不评估、也不授权 G5a。可用以下只读命令查看
状态：

```bash
uv run python code/warning/ootang_v5_gate_preflight.py --report
```

默认运行或显式传入 `--require-g0-g4` 在当前状态下必须 fail closed。
CLI 只读生产默认 register，不提供路径替换。生产中的 `require_g0_g4_preflight()`
同样固定使用唯一默认 register，不接受 path 或 root 参数。任何未来 G5a runner
必须先把它作为首个业务
动作：在读取标签、训练数据或其他 payload 之前，也在创建输出目录、
模型、预测或 manifest 之前运行该预检。静态 stage 选择、命令行参数或手工
调用都不能替代该业务门。

即使 G0--G4 全部 PASS，也只满足 G5a 的必要条件，不代表 G5a 自动获授权。
真正的 G5a 还需单独版本化的 run contract，至少冻结特征、搜索空间、
随机种子、calibration 流程、平局/失败规则、输入与实现哈希、一次性输出
namespace，并由另一个运行前 guard 验证。该 contract 和 guard 当前均未实现；
所以不得运行 NGBoost。

本次 G1--G4 预检仅做只读证据盘点与门状态实现：没有读取标签
payload，没有训练或运行 NGBoost，没有生成融合/预警输出，也没有读取
或修改 Vajont 工作簿与根目录 `review.md`。

## 2. 当前已知事实

自动 V0 候选只使用 fit 段，当前结果为：

- MJ1、MJ3：`initial_segment_selected`，候选 V0 可用；
- ATU1、ATU2、ATU3、ATU4、ATU5：`first_break_is_not_accelerating`；
- MJ9：`nonpositive_initial_segment_slope`；
- 后六站均为 `unavailable`，其 V、速度标准差、V0 和 V0 依赖字段必须为空。

2026-08-20 的数值审计已关闭：ATU3/MJ9 原 `negative_segment_sse` 来自全历史 float64 前缀原始矩相减的灾难性消减；统一的逐候选段局部统计修复后，八站均先完成相同 DP/BIC 分段，再进入科学门禁。原六站边界和状态不变，MJ1/MJ3 的物化 V0 不变，共享 v4 实现与 97 个保护文件不变。完整证据见 `docs/v5_v0_numerical_audit.md`。

这些状态仍是候选诊断结果，不是经现场验证的正式 V0。数值门关闭只说明当前 2/8 可用率不再由实现异常造成，不能把 6/8 不可用解释为现场稳定阶段已经被证伪，也不能据此设计、训练或评价正式 v5。

G1--G4 现有证据的完整盘点见 `docs/v5_g1_g4_preflight.md`。其确认：

- 当前没有独立五级现场真值、事件文件或标签 manifest；
- 藕塘物化数据仅覆盖 2016-07-01 至 2020-06-30，已有切分和滚动验证已暴露其可用时间范围，当前无 unseen 确认块；
- candidate-display 的 V0 可用覆盖为 2/8 站、1,028/4,112 点日，均为 25%，当前正式 site 输出为 0/514 日；
- `R_min`、`FAR_max`、`delta_min`、各层 `coverage_min` 和最低支持量等数值门槛仍为 null，未获批准。

## 3. 正式验证问题与预测单位

正式协议必须在任何模型选择前，把下列项目写入一个版本化配置并冻结：

1. **发布单位**：逐测点还是滑坡体级；若两者都评价，二者必须使用独立指标和分母。
2. **发布时间点**：在日期/时刻 `t` 可使用的数据截止规则，包括迟到数据和非规则采样的处理。
3. **预测时间窗 `H`**：例如未来 1、3 或 7 个自然日，只能预先选定一个主时间窗；其他时间窗只能作为明确标注的敏感性分析。
4. **目标事件**：预测窗口内何种现场事实构成阳性，以及五级标签是否确有独立现场含义。
5. **可行动阈值**：何种站点或滑坡体输出触发行动，行动成本和可接受的漏报/误报边界。

已有 h=1/3/7 的 NGBoost 试验属于已查看的内部探索，不能依据其历史 test 表现反向选择正式 `H`。

## 4. 标签冻结门

### 4.1 可接受的标签来源

正式标签必须来自与候选规则、v4 输出和 NGBoost 预测相互独立的证据，例如带时间戳的现场事件记录、经预先定义规则整理的工程处置记录，或不知道模型输出的专家双人标注及独立仲裁。标签文件至少应包含：

- 站点/滑坡体标识、事件开始和结束时间、信息可见时间；
- 标签级别、标签来源、证据链接或来源编号；
- `positive`、`negative`、`unknown`/不可判定的明确区分；
- 两名标注者、分歧和仲裁结果（使用专家标注时）；
- 与主预测时间窗 `H` 对齐的确定性生成规则；
- 数据版本、生成代码版本和 SHA-256。

`unknown` 不得转为绿色/阴性，也不得为提高样本量而插补。若五级现场真值没有充分依据，应预先改成较少级别或二元事件目标，不能先看模型结果再合并类别。

### 4.2 不可接受的标签

以下内容不能充当正式真值：

- v4 的站点颜色、滑坡体颜色、阈值或融合结果；
- 当前候选展示的 `interval_level`、速度比、切线角或 V0 状态；
- NGBoost interval-proxy 试验的规则代理标签；
- 由待评价模型自身生成、筛选或修订的标签；
- 仅凭图形目视、事后挑选“典型日期”得到的标签。

### 4.3 冻结证据

在首次正式训练前必须生成只读的标签清单和 manifest，记录标签定义、覆盖日期、类别计数、未知数、事件数、来源哈希、代码哈希、冻结时间和批准人。标签定义或内容一旦改变，原验证轮次立即失效，必须增加协议版本并重新开始；不得保留较有利的旧结果与新标签混用。

当前状态：`BLOCKED`——项目尚无已冻结的独立正式标签。

## 5. 时间切分与数据泄漏控制

### 5.1 已有数据的角色

当前全站统一时间边界为：

| 数据段 | 日期 | 在本协议中的角色 |
|---|---|---|
| model fit | 2016-08-06 至 2019-02-02；911 日/7,288 点日 | ConvLSTM/模型内部训练与特征统计；不定义自动 V0 的起点 |
| automatic V0 selection window | 2016-07-01 至 2019-02-02；每站 947 行、共 7,576 点日 | 仅用 fit 截止日以内的运动学做自动分段与候选 V0；2016-07-01 至 2016-08-05 是 V0-only 前导窗口 |
| calibration | 2019-02-03 至 2019-09-17；227 日/1,816 点日 | 内部调参与阈值设计 |
| historical test | 2019-09-18 至 2020-06-30；287 日/2,296 点日 | 已多轮查看的回顾性评价，不再是盲测确认集 |

已有 calibration 和 historical test 可以用于方法开发报告，但必须标注 `retrospective_internal_only`。它们不能支撑确认性性能、泛化、提前量或正式预警声明。

### 5.2 正式确认集

正式确认需要一个在协议、标签、特征、模型、阈值和融合规则全部冻结后才解封的独立时间块。优先使用后续未见的藕塘数据；也可在另行批准的数据源上做外部验证，但不得自动引入 Vajont。确认集的开始/结束日期、事件数、类别支持量和解封负责人必须在运行前写入 manifest。

若无法获得未见确认集，项目最多只能报告“内部回顾性 v5 原型”，不得报告“正式 v5 验证通过”。

### 5.3 强制防泄漏规则

- 所有测点按同一完整日期块切分；禁止随机拆行，避免同一日期或同一事件跨段泄漏。
- V0、分段、标准化、缺失策略、特征选择、超参数、概率校准、等级阈值和融合参数不得读取确认集。
- 任一 `t` 时刻特征只能使用 `t` 当时可获得的数据；目标窗口、移动窗口和滞后量不得跨越切分边界。
- 自动 V0 的 selection window 固定为 2016-07-01 至 model-fit 截止日
  2019-02-02；不得用 calibration、historical test 或正式确认集重新估计。
- calibration 用于一次预先声明的选择流程；默认不在 fit+calibration 上重拟合。若将来需要重拟合，必须在确认集解封前单独修订并冻结协议。
- 正式确认集只运行一次。发现实现错误时，应记录失败原因、保留原输出并增加验证轮次版本，不能静默覆盖。

当前状态：`BLOCKED`——历史 test 已被查看，新的未见确认时间块尚未冻结。

## 6. V0 unavailable 的正式处置

### 6.1 Fail-closed 规则

对任一 V0 不可用站点：

- 保留原始观测、速度、`ΔV`、区间信息和不可用原因；
- V、速度标准差、V0、`velocity_ratio`、V0 依赖切线角和相应分支分数保持空值；
- 分支状态固定为 `not_applicable_v0_unavailable`；
- 不得把不可用解释成绿色、零风险或无事件；
- 不得手工选稳定日期、借用其他测点/历史 v4 的比较器、使用 KMeans 回退、插补、外推或以常数替代 V0；
- 不得为提高覆盖率而放宽分段规则或按 calibration/test/标签表现调参。

### 6.2 评价分母与覆盖率

所有结果必须同时报告：总测点/日期数、V0 可用数、不可用数、每种不可用原因，以及按标签类别分层的覆盖率。只在 MJ1/MJ3 上得到的结果必须明确写作“V0 可用子集（2/8 站）”，不能外推为八站性能。

不可用记录不能从总体分母中静默删除。若方法只对可用子集评分，应并列报告：

1. 可用子集的性能；
2. 全体部署范围的覆盖率；
3. 将不可用视为“无输出”时的系统级可用性。

在没有预先冻结并独立验证的 availability-aware 融合规则前，任一需要八站完整 V0 分支的滑坡体级融合必须停止，不得临时改用可用站点投票。若未来新增“不依赖 V0 的替代分支”，它必须作为新方法独立训练和验证，不能称为缺失值回退。

数值审计若改变 ATU3/MJ9 的状态，只能从原始 fit 数据按修正后的版本化实现重新生成全部候选产物；必须保存修正前后差异和哈希，且不得用标签或后期数据决定修正。

当前状态：`BLOCKED`——数值审计已关闭，但八站部署范围的 availability-aware 政策和覆盖率门槛尚未获批准。

## 7. 比较基线

正式评价至少保留以下基线，并使用相同标签、发布时间、预测时间窗、可用样本和置信区间：

| ID | 基线 | 作用与限制 |
|---|---|---|
| B0 | fit 类别先验/多数类或恒不报警 | 检查类别不平衡；accuracy 不得作为其主要优势证据 |
| B1 | 上一可见状态持续（persistence） | 检查时间序列中“状态不变”带来的虚高表现 |
| B2 | 冻结的 v4 operational draft | 只作为历史规则比较器，仍用独立标签评价；不得当作真值 |
| B3 | NGBoost-only | 判断概率模型本身是否有效 |
| B4 | 冻结的 V0/运动学规则-only | 判断候选规则本身是否有效，仅限明确可用范围 |
| B5 | v5 fusion | 仅在 B3、B4 分别过门后评价其增量价值 |

比较必须逐时间点配对，并按日期块或独立事件做置信区间；不能把高度相关的“测点×日期”行当成相互独立样本。若某基线因 V0 unavailable 无法输出，必须按同一无输出政策计入覆盖率，不能只比较两者共同成功的有利子集而不另行披露。

## 8. 指标与通过标准

### 8.1 主指标

正式运行前须由工程/导师决策冻结两个共同主指标及数值门槛：

1. **事件召回率**：事件在预先定义提前窗内至少一次达到行动阈值的比例；
2. **误报警率**：每 100 个有独立标签且为阴性的测点发布日（滑坡体输出则为阴性滑坡体发布日）的误报警次数。

二者是共同约束，不合成为事后可调的单一分数。必须预先填写最低事件召回 `R_min`、最大误报警率 `FAR_max`、最小事件数和置信区间规则；未填写时不能选择阈值或声明通过。

### 8.2 次指标

- 事件首次正确报警提前量的中位数、四分位数和逐事件列表；
- 五级/有序标签存在时的 macro-F1、逐类 recall、ordinal MAE 和 quadratic weighted kappa；
- 概率输出的 multiclass log loss、multiclass Brier、top-label ECE 及逐类可靠性；
- 混淆矩阵、状态转移子集指标和持续状态子集指标；
- 输出覆盖率、V0 unavailable 率、无输出持续时间和失败原因分布；
- 测点级和滑坡体级分别报告，不得合并成一个总 accuracy。

缺失类别对应的 recall/AUC/校准指标记为 `NA` 并写明 `unsupported_class`，不得记为 0 或从汇总中无声删除。指标置信区间应按事件或连续日期块重采样；事件数不足时报告精确计数和宽区间，并保持验证门未通过。

### 8.3 通过逻辑

正式 v5 至少应同时满足：

- 在确认集达到冻结的 `R_min` 与 `FAR_max`；
- 相比 B0/B1 不仅提高 accuracy，而且改善预先指定的概率或有序主次指标；
- v5 fusion 相比 B3、B4 中较强者达到预先冻结的最小增量 `Δ_min`，且不突破误报约束；
- 关键事件/类别具有预先冻结的最低支持量；
- 覆盖率达到预先冻结的 `coverage_min`，且不可用没有被当作阴性；
- 所有结果可由锁定输入、配置和代码哈希复现。

`R_min`、`FAR_max`、`Δ_min`、`coverage_min` 和最低支持量当前均为待工程决策项，必须在确认标签或结果解封前填入版本化配置，不能根据 test 结果补写。

## 9. 阈值、概率校准和模型选择

1. V0 与其统计量只在 fit 段生成；其公式或分段超参数的任何更改都视为新方法版本。
2. NGBoost 的特征集、预测时间窗、超参数搜索空间、随机种子集合和选择指标须先冻结；fit 只用于拟合，calibration 只用于已登记的模型选择。
3. 概率校准方法、概率到行动等级的阈值网格/优化器、约束、平局规则和失败规则须在运行前写入配置；只允许使用 calibration。
4. 融合权重、证据 family、空间支持数、V0 unavailable 分支和颜色映射均视为阈值的一部分，只允许在 fit/calibration 阶段按冻结流程确定。
5. 若 calibration 缺少某一行动类别或事件数低于最低支持量，该类别阈值不得估计；应收集数据或在解封确认集前预先改变目标定义。
6. historical test 和正式确认集不得参与特征、时间窗、超参数、概率校准、阈值或融合选择。
7. 结果不达标时保持失败结论。不得在查看确认集后调阈值并把同一数据再次称为 test。

最终冻结物至少包括：标签 manifest、split manifest、特征清单、模型配置、阈值/融合配置、依赖锁、实现代码哈希、输入哈希和一次性运行命令。

## 10. NGBoost 与融合的进入条件

### 10.1 NGBoost 生成门与验收门

NGBoost 分为运行前的 G5a 和运行后的 G5b，避免用尚不存在的 calibration
结果作为生成该结果的前提。这两个名称表示严格先后阶段，不是两个
可相互解锁的 register Gate：G5a 不存入 G0--G4 register；G0--G4 全部
PASS 只是 G5a 必要条件，还须由独立版本化 run contract 和专用 guard 授权。
G5b 只能在 G5a 产物已存在后记录对该产物的验收结论，
永不能反过来作为生成自身证据的前置条件。

只有以下条件全部满足，G5a 才可批准生成一次新的 **calibration-only 候选
推理产物**，并把该候选 manifest 的 `ngboost_inference_output` 设为 true：

- G0--G4 全部通过；
- V0 数值审计已关闭，且 NGBoost 输入不依赖任何未审计或被插补的 V0 字段；
- 独立标签、主预测时间窗、全站同日期切分和特征可用时间检查已冻结；
- NGBoost 的目标是独立标签，而非 v4/interval proxy 自生成标签；
- 特征、搜索空间、随机种子、概率校准、平局/失败规则和 B0/B1 进入标准已在运行前版本化；
- 正式确认集仍封存，候选运行只能读取 fit 与 calibration；
- 输出使用新 namespace，明确 `candidate_only=true`，并记录模型、输入、随机性和输出 manifest。

上述与标签、时间、availability 和指标相关的条件必须被 G1--G4 的决策、
证据和批准范围覆盖。特征、搜索空间、seed、calibration 流程、失败
规则、输入/实现哈希和一次性 namespace 则由单独 G5a run contract 冻结。
未来 runner 必须先后通过 G0--G4 预检与 G5a 专用 guard，两者都必须在首次
payload 读取或任何产物写入前完成。

G5a 只授权产生待验收证据，不代表 NGBoost 分支已经进入 v5。候选运行结束
后，只有 calibration 上相对 B0/B1 达到预先冻结的标准、概率校准和类别支持
合格、复现检查通过，G5b 才可标为 PASS；失败则保留候选诊断并停止，不得
通过同一 calibration 反复改规则。

现有 NGBoost interval-proxy pilot、horizon sensitivity 和 feature ablation 只能提供内部探索证据，不能直接晋升为正式 v5 NGBoost 分支。

### 10.2 融合生成门与验收门

融合也分为运行前的 G6a 和运行后的 G6b。只有以下条件全部满足，G6a 才可
批准生成一次新的 **calibration-only 候选融合产物**，并把该候选 manifest
的 `v5_fusion_output` 设为 true：

- G5b 已通过，且规则/V0-only 分支的 calibration 候选也通过各自冻结的进入门；
- 两个分支使用同一发布时间、预测窗和独立标签；
- 已检查相关/重复证据，并在运行前冻结避免重复计票的 family 规则；
- availability-aware 行为已明确到每种缺失组合，且六站不可用不会被绿色化、填补或静默删除；
- `Δ_min`、误报约束、融合规则、空间拓扑、支持数、阈值、平局和回退失败策略均已版本化；
- 独立确认集尚未解封，输出使用新 namespace 并明确 `candidate_only=true`。

候选融合产生后，只有 calibration 上相对 B3/B4 中较强者达到冻结的
`Δ_min`、同时满足误报和覆盖约束且复现检查通过，G6b 才可标为 PASS。
G6a 不是 G6b；G6b 不能作为 G6a 生成同一产物的前提，未过 G6b 的
产物只能保留为失败诊断。未来的融合 runner 也必须在任何 payload I/O 之前
验证上一阶段验收证据与已冻结的融合契约，不得用待生成的融合结果解锁自身。

只有候选融合在独立确认集一次性通过全部主指标、覆盖率和复现门，才可讨论 `formal_warning_output=true`。该标志变化需要单独的人为批准，不能由脚本根据单次指标自动开启。

## 11. 明确禁止事项

- 禁止在数值审计关闭前启动正式 v5。
- 禁止把 candidate-display 改称正式结果或添加无资格的候选/正式颜色列。
- 禁止使用 calibration、historical test、正式确认集或标签挑选稳定段与 V0；它们只能由 fit 期的冻结无标签算法产生。
- 模型、预测窗、特征、概率/行动阈值和融合规则只可按运行前冻结的流程使用 fit/calibration 选择；historical test 与正式确认集永不得参与选择。
- 禁止手工 V0、KMeans 回退、借用 v4 比较器、跨站借值、插补、常数替代或按结果放宽门槛。
- 禁止把 unavailable、unknown、缺测或无输出编码为绿色/阴性。
- 禁止用 v4 或模型自身输出作为正式标签。
- 禁止覆盖历史 v4、ConvLSTM、NGBoost 或候选展示产物；新轮次使用新目录和新 manifest。
- 禁止读取、适配、运行或用 Vajont 工作簿做验证；任何 Vajont 工作都需要用户另行明确授权和独立协议。
- 禁止因 test 不理想而静默重跑、筛种子、改阈值或只报告有利站点/日期。

机器 register 只存储并验证 G0--G4。G5a 是其后独立实现的运行前授权，
不由 register 直接推导。G5b/G6b 是已有候选产物的事后验收记录，
G6a 是其后的新一次运行前授权。
该顺序禁止用 G5b 解锁产生 G5b 所需产物，也禁止用 G6b 解锁产生 G6b
所需产物；任何未到达阶段都不得用一个手工布尔值跳过。

当前已经物化的 candidate-display bundle 处于 G1--G4 均 BLOCKED、
G5a 未授权且后续阶段均未到达的阶段，
其 manifest 必须继续保持：

```text
candidate_display_only=true
candidate_warning_color_output=false
ngboost_inference_output=false
v5_fusion_output=false
formal_warning_output=false
vajont_used=false
```

这些值描述当前 bundle，不是把后续候选阶段永久锁死。阶段开关按以下规则
递进，任何后续阶段都必须写入新的 artifact namespace 和 manifest：

- G0--G4 任一项未通过时，`ngboost_inference_output=false` 且
  `v5_fusion_output=false`；
- G5a 获批后，新的 calibration-only NGBoost 候选产物可令
  `ngboost_inference_output=true`，同时必须明确 `candidate_only=true`，且
  `v5_fusion_output=false`；该开关不表示 G5b 已通过；
- G6a 获批后，新的 calibration-only 候选融合产物可令
  `v5_fusion_output=true`，仍须标记为候选；该开关不表示 G6b 已通过，G7
  运行期间也不得冒充正式预警；
- `formal_warning_output=false` 在 G8 通过并取得单独人工批准前始终不变；
- 当前 display 中 `candidate_warning_color_output=false`；若未来候选融合需要
  颜色，必须在 G6a 前另行冻结语义、阈值和 unavailable 行为，不能复用
  当前 display 的字段作默示授权；
- 本协议的藕塘运行始终 `vajont_used=false`。Vajont 只能依据另行授权和独立
  协议启动。

后续每次改门状态，应在本节记录日期、证据路径、commit、批准人和理由；不得只在对话中确认。

## 13. 下一步执行顺序

1. 数值门 G0 已于 2026-08-20 关闭；后续数值实现变化必须重新打开该门并重跑同等审计。
2. 与导师/工程方冻结独立标签定义、主预测时间窗和行动代价；在任何正式模型训练前生成标签 manifest。
3. 盘点未见藕塘数据并冻结确认时间块；若不存在，明确将本阶段限定为内部回顾性原型。
4. 冻结 V0 unavailable 的部署政策、覆盖率门槛、基线、主指标数值门槛和阈值选择算法。
5. G0--G4 全部通过并冻结 G5a 运行契约后，才生成一次 NGBoost calibration 候选供 G5b 验收；G5b 通过并冻结 G6a 运行契约后，才生成一次融合 calibration 候选供 G6b 验收。
6. 锁定代码、配置和输入后一次性运行确认集，最后由人工决定是否允许正式输出。

在以上顺序完成前，当前最远边界仍是 2/8 站 V0 可用的探索性 candidate-display，不能进入正式 v5。
